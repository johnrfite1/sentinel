## The newest and least-reviewed thing here is the E3 repair (A-075)

The signer now pins every state and code read to ONE block and requires the receipt's anchor to
equal that exact block number AND hash. Two new reason codes: `SIGNER_ANCHOR_NOT_OBSERVED`
(CONFORMANCE) and `SIGNER_CHAIN_UNSTABLE` (FATAL).

**Attack it.** Can you get an ALLOW anchored to a block the signer did not read? Can the
snapshot straddle two blocks? Does the retry loop terminate, and what happens when it does not?
Is `SIGNER_ANCHOR_NOT_OBSERVED` reachable in a way that makes Case 4 unreachable? **Is the new
behaviour — refusing a caller whose simulation is one block stale — actually what the code
does, or does some path still accept a stale anchor?**
